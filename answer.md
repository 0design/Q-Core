Відхилення людського gate тепер пропускає залишок його структурної гілки, а незалежні гілки продовжують виконання. Завершений прогін має статус `rejected`; справжня технічна помилка, як і раніше, дає `failed`.

**Причина.** У `src/run.mjs`, `resumeConfirmedRun()` прямо присвоював gate і прогону `failed` та повертався без `driveRun()`. Тому зупинявся весь прогін.

| Було | Стало |
| --- | --- |
| Reject зупиняє весь прогін як помилку | Gate стає `rejected`, його невиконаний залишок — `skipped`; виконання продовжується до наступної зупинки |
| Немає окремого підсумку відхилення | Підсумок рахує відхилені gate; `rejected` — термінальний, без повторного виконання ефектів |
| Відхилений child міг вимагати відсутні outputs | Call/return теж стають `rejected`, outputs не зв'язуються, залежне продовження батьківської гілки пропускається |
| Host не знає нового термінального статусу; текстовий CLI міг повернути успіх | Host допускає наступну подію; CLI показує відхилення та повертає 1 і в тексті, і в JSON |

Пропозицію Air скориговано: сканування батьківської гілки після відхиленого child починається **після child return**, з межами його call. Початковий варіант зупиняв цей скан на першому child row й міг виконати батьківську доставку.

Семантика approve, таймаутів і Touch ID не змінена. Перевірки persisted snapshot, subject hash, підпису, nonce, строку дії та одноразовості рішення залишаються перед зміною стану. Production-код підтверджень і preview не змінювався.
