# Результати реальної перевірки core.11

Це реальні виконання на синтетичних задачах, а не прийнятий власником ХУЇКС-Дайджест. Дві свіжі сесії Codex отримали точні промпти сайту, завантажили пакет через HTTP й перевірили контрольні суми. Генерація відбулась у батьківській сесії; Core застосував зміни, запустив тест і виконав підтверджену доставку.

## SDD: нормалізація тегів

Задача: створити normalizeTags(input), яка прибирає пробіли, переводить рядки в нижній регістр, відкидає порожні/нестрокові значення, прибирає дублікати зі збереженням порядку й не змінює вхідний масив. Український регістр теж перевіряється.

До: tags.mjs не існував. Після: [готова функція](tags.mjs).

Приклад входу: `['  JavaScript ', 'JAVASCRIPT', ' Їжак ', '', '   ', 42, null, 'КИЇВ', 'київ']`.
Результат: `['javascript', 'їжак', 'київ']`; вхідний масив не змінений.

[Незалежний тест](verify-tags.mjs) збережений незмінним від моменту підтвердження специфікації. Core виконав його з exit 0; окремий повторний запуск теж пройшов. Повторне звернення до завершеного Core run повернуло збережений success без нового inference.

## Content: sourced draft і доставка

Джерело — спеціально написана вигадана новина про команду Orchard. [Збережений текст](digest.txt):

> Синтетичний тест: вигадана команда Orchard додала три незалежні перевірки до локального процесу релізу, що посилює контроль його якості. Джерело: http://127.0.0.1:58415/source/1

Точний текст і тестовий отримувач були окремо підтверджені синтетичним test-owner. Отримувач зафіксував рівно один POST та receipt synthetic-1. [Квитанція](receipt.json); [повторний запуск](repeat.json) повернув no_new_sources. Текст отримувача збігається зі збереженою чернеткою.

## Межі доказу

- Це локальний сайт та тестовий отримувач, не публічний реліз і не реальний канал власника.
- SDD у цьому проході використав імпортовану специфікацію та пройшов тест з першого разу. Додатковий контрольований regression уже довів actual fail→caller repair→pass: див. нижче.
- Поточний agent/model — заявлена ідентичність. Core не підтверджує назву фактичної моделі та не має виміряної вартості; ці поля лишаються null.
- Claude ще не перевірено. Customize/Create мають окремі результати нижче; це прості локальні сценарії, не доказ довільного проєкту.

[Машинні перевірки й контрольні суми](checks.json). Оригінальні діалоги: ../golden-parent/start-caller-ready/ та ../golden-parent/use-caller/.

## Контрольоване виправлення після помилки

В окремій папці тестовий власник явно попросив навмисно неправильну першу реалізацію — повернення порожнього масиву. Core реально запустив незмінений тест: exit 1. Він видав нове завдання на виправлення, Codex подав правильну реалізацію, Core знову запустив той самий тест: exit 0. Два завдання одноразово спожиті. Це контрольована інʼєкція помилки, не випадкова помилка моделі. [Повний стан](repair-state.json).
