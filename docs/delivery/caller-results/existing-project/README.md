# SDD у наявному проєкті — перевірено

Це контрольований локальний проєкт із уже наявними незакоміченими змінами. Свіжа сесія Codex отримала точний промпт сайту й використала core.11 через HTTP.

Задача: виправити лише normalizeTags, зберегти існуючий helper і коментар користувача. Специфікацію згенеровано відповіддю на caller-завдання Core: `specOrigin=intent`, готову специфікацію не імпортовано. Після окремого підтвердження точного hash Core прийняв другу одноразову відповідь — файли — та сам застосував зміну й запустив наявний тест.

- [До](tags-before.mjs) · [Після](tags-after.mjs) · [Точна різниця](change.diff).
- `[" JS ", "js", " ЇЖАК ", "київ", "КИЇВ", "", 42, null]` → `["js", "їжак", "київ"]`; вхідний масив не змінено.
- README з незакоміченим текстом, settings.json, untracked private-notes.txt, staged-plan.txt і verify-tags.mjs збережені байт у байт.
- Історія Git і staged diff не змінені. Наявний helper і коментар у tags.mjs збережені.
- Наявний незмінений тест пройшов у Core та в окремому перевірочному запуску.
- Повтор повернув ті самі артефакти й докази; нове завдання генерації не створювалося.

[Машинні перевірки](checks.json), [початковий знімок](before.json), [стан запуску](run-state.json), [повтор](repeat.json).

У діалозі була помилка інтеграції: агент спершу забув resumeRunId. Core відхилив відповідь без зміни файлів; агент сам відновив правильний запуск. Цей факт збережено, а не приховано. Пізніше Site уточнив інструкцію; цей прохід не переоцінюється за новим текстом.

Межі: синтетичний проєкт і test-owner approval, не приймання власником. Доказ стосується перелічених файлів та станів; він не гарантує безпечність усіх довільних проєктів. Додаткові файли встановлення/стану зберігаються в untracked .qf. Публікацій і зовнішніх записів не було; Claude тут не перевірявся.
